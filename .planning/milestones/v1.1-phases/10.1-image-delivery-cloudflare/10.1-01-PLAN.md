<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> Cloudflare edge | After orange-cloud flip, ALL requests to bbq-experience.com traverse Cloudflare; TLS terminates at CF, not at Caddy. |
| Cloudflare edge -> cms.bbq-experience.com origin | The Transformations feature fetches from cms.bbq-experience.com on behalf of a client /cdn-cgi/image/ request. Sources allowlist is the trust filter. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10.1-01 | I (Information Disclosure / SSRF) | Cloudflare /cdn-cgi/image/ fetcher | mitigate | Task 1 explicitly limits Sources allowlist to exact subdomains `bbq-experience.com` and `cms.bbq-experience.com`. Do NOT add `*` wildcard. Task 2 probes a non-allowlisted host (e.g. `example.com`) and asserts 4xx — otherwise the allowlist is too permissive. |
| T-10.1-02 | T (Tampering) | Image URL path-parameter injection | mitigate | Plan 02 will URL-encode the origin URL before concatenation; this plan does not yet emit URLs. Threat is tracked forward to Plan 02 Task 1. |
| T-10.1-03 | D (Denial of Service) | Cache-miss flood at CF edge | accept | Traffic volume is low (editorial site, ~500 uniques/day). CF Free plan free bandwidth. Not blocking for ASVS L1. |
| T-10.1-04 | R (Repudiation) | Dashboard config change with no audit trail in repo | mitigate | SUMMARY.md artifact records the before/after probes with timestamps so the state change is git-attested even if CF dashboard history is opaque. |
</threat_model>
