## Discoveries from Overnight 2026-05-26→27

### Bug 1 — Queue not synchronized cross-machine

**Symptom:** `meta_optimizer` on `.119` generated 20 proposals overnight; `meta_review` on Windows had nothing to consume at 09:00.

**Root cause:** State files live on different filesystems. Phase 17-02 smoke test only validated each side isolated, never the actual hand-off.

**Fix:** `scripts/agents/meta_review.cmd` extended with pre-step `scp` from `.119` + post-step `ssh truncate` of remote pending. Atomic-safe (Python reads all-in-memory before truncate).

**Result:** 20/20 proposals processed live. **18 reject + 2 approve + 0 needs_human**. 2 articles modified in Strapi (live PUT with skip_rebuild=True).

### Bug 2 — Windows Task Scheduler "Solo interattivo" mode (UNFIXED — Matteo action required)

**Symptom:** "BBQ Meta Review" task showed "Pronta" but never actually ran at 09:00 (no log file, no proc trace).

**Root cause:** `schtasks /Create` without `/RU SYSTEM` or explicit credentials defaults to "interactive only" — task fires only if user is logged in with active console session.

**Attempted fix:** `schtasks /Create /RU SYSTEM /RL HIGHEST /F` → ERR Access Denied (orchestrator shell not admin-elevated).

**Matteo action required (1 of 2):**

Caveat: Claude CLI under SYSTEM may fail OAuth Pro Max path (no user profile).
- **Option B (recommended):** Task Scheduler UI → BBQ Meta Review → Proprietà → check "Esegui anche se l'utente non ha effettuato l'accesso" → inserisci tua password Windows → OK. Task gira con tua identità (Claude CLI ha tuo profilo).

**Workaround actual:** orchestrator launched `meta_review.cmd` manually 09:21 stamattina; 20 proposals consumed end-to-end. Validation done. Tomorrow 09:00 same fragility unless Matteo applies Option A or B.

### Bug 3 — FAQ parser markdown-only (no HTML detection)

**Symptom:** Sweep schema 268/287 (93.4%) post Phase 18 — 19 pagine "Visible FAQ but NO FAQPage JSON-LD".

**Root cause:** Real Strapi content for many articles is **HTML directly** (`<p>Intro</p><h2>Frequently Asked Questions</h2><h3>Q?</h3>...`), not markdown (`## FAQ\n### Q?\nA`). Phase 18 parser-v2 only handled MD case.

**Fix:** `detectFaqFromMarkdown` extended with HTML fallback (`detectFaqFromHtml`) — strips inner tags from `<h2>`, uses universal FAQ heading (acronym international, works across all locales when content uses "FAQ" in English even in IT/ES articles), supports both `<h3>Q?</h3><p>A</p>` AND `<p><strong>Q:?</strong><br>A:</p>` Q-A patterns.

**Additional sweep fix:** `_has_visible_faq` updated to (a) use `get_text(separator=' ', strip=True)` to handle nested tags (`<a>`) inside `<h2>` (was producing `"FAQ AboutBBQ GrillCleaners"`), (b) accept suffix lookahead patterns (mirror parser regex).

**Result:** Sweep PASS 268 → 284 (+16 recoveries, 98.96%).
