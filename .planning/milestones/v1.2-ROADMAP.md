## Overview

v1.2 è un milestone di **consolidamento** dopo il big-feature push di v1.1. Tre obiettivi:

1. **Polish del Phase 17 GSC pipeline** (Phase 18): chiudere i deferred-items emersi dal sweep schema live + dry-run quality gate
2. **Tech debt cleanup** (Phase 19): pre-existing TS errors, Phase 10 missing VERIFICATION, Phase 14 unfinished plan, state files orphan

Sequencing: tutte e 3 le phases sono additive e non hanno deps cross-phase forti — possono partire in qualsiasi ordine, ma seguo numeric per coerenza con convenzione progetto.

**Goal**: Chiudere i 3 deferred-items emersi dalla execution Phase 17 — recuperare le 19 pagine FAQ non rilevate (6.6% del sito), aggiungere protezione `topical_relevance` al quality gate (visto in dry-run weber-kettle), enable Indexing API GCP + verify funziona, garantire IndexNow re-ping su ogni refresh promotion.
**Depends on**: Phase 17 (deployed + live measurable)
**Requirements**: SEO-13, SEO-14, SEO-15
**Success Criteria** (what must be TRUE):
  1. `web/src/lib/structured-data.ts` `FAQ_HEADING_PATTERNS` aggiornato con lookahead positivo per suffix legittimi (`about|on|for|regarding|—`). Test guard `## FAQ at a barbecue` continua a fallire correttamente. Sweep `python scripts/sweep_pages.py --check schema` reports PASS rate ≥ 97% (≥282/287 pages) — recupera le 19 pagine FAQ-suffix non rilevate da Phase 17.

Quality gate flagga sezioni semanticamente fuori scope rispetto al titolo (verificato manualmente sul weber-kettle dry-run: 3 sezioni "electric kettle"/"basketball"/"banjo" devono produrre `topical_relevance: critical` o `major` issue).

  4. `gsc_refresh_review.py` su ogni successful promotion (publish post-quality-gate) chiama `indexnow_client.ping(url)` IN AGGIUNTA a Indexing API (Phase 17 chiamava solo Indexing). Verificato in test unitario.

### Phase 20: Outcome Measurement Framework
**Goal**: Shippare l'infrastruttura per misurare il lift CTR atteso dal Phase 17 GSC pipeline nei prossimi 30 giorni (~2026-06-25), così Matteo ha decision-tree esplicito per interpretare i risultati.
**Depends on**: Phase 17 (baseline + live pipeline), Phase 18 (clean state per measurement)
**Requirements**: MEASURE-01, MEASURE-02, MEASURE-03
**Success Criteria** (what must be TRUE):
  1. `scripts/agents/phase17_outcome_tracker.py` esiste su `.119`, cron weekly (es. Lun 09:00 UTC), legge GSC top_pages 28d + traffic_score Strapi + state/meta_changes.jsonl + state/gsc_refresh_success.jsonl. Confronta con baseline 2026-05-25 (35 clicks / 29k impressions / CTR 0.12% / pos 6.7) e produce report.
  2. Report Telegram weekly "Phase 17 Outcome Tracker" con: delta CTR % vs baseline, n articoli con meta cambiati nella settimana, n articoli regenerated, top 5 climbing (CTR ↑↑), top 5 declining (CTR ↓↓), action_recommendations basate su decision tree (es. "lift < 3× target dopo 14 giorni → revisit meta_optimizer prompts").
  3. `.planning/milestones/v1.2-phases/20-outcome-measurement/decision_tree.md` documenta esplicitamente i trigger:
     - lift 10×+ entro 14gg → success, scale gsc_refresh weekly
     - lift 3-10× entro 14gg → on-track, no action
     - lift <3× entro 14gg → revisit meta_optimizer power-words IT/ES + Qwen prompt
     - lift <1.5× entro 30gg → degraded, manual review top 5 meta_optimizer proposals + rollback se necessario
