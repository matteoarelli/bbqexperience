For each of the 15 targets in `selected-slugs.json`, run Lighthouse and write the JSON report to `.planning/artifacts/lighthouse-v1.1-baseline/{id}.json`.

Preflight: verify lighthouse is available. Prefer global installation if present; fall back to npx:
```bash
which lighthouse || npx --yes lighthouse --version
```

Run loop (bash):
```bash
cd .planning/artifacts/lighthouse-v1.1-baseline
jq -r '.targets[] | "\(.id)\t\(.url)"' selected-slugs.json | while IFS=$'\t' read -r id url; do
  echo "[Lighthouse] ${id} -> ${url}"
  npx --yes lighthouse "${url}" \
    --only-categories=performance,accessibility,best-practices,seo \
    --form-factor=mobile \
    --throttling-method=simulate \
    --output=json \
    --output-path="./${id}.json" \
    --chrome-flags="--headless=new --no-sandbox --disable-gpu" \
    --quiet
  sleep 2
done
```

Use mobile form factor to match DES-04 original ("real mobile hardware" per v1.0-ROADMAP.md Phase 09 success criterion 1). Throttling simulated is acceptable for CI-style repeatability.

If a run fails (Chrome crash, network timeout), retry up to 2 times with 10-second sleep between attempts before moving on. If still failing after 3 attempts, write a stub file `{id}.json` with content `{"error": "failed after 3 retries", "url": "..."}` and note it in Task 3's SUMMARY.

- `categories["best-practices"].score`
- `categories.seo.score`

Quick validation after each run:


Note: This task may take 30-60 minutes (15 runs x ~2-3 min each including throttled mobile simulation). This is inherent to Lighthouse, not over-scope.

Extract scores from each JSON report:
```bash
cd .planning/artifacts/lighthouse-v1.1-baseline
for id in home-en home-it home-es review-en review-it review-es recipe-en recipe-it recipe-es tutorial-en tutorial-it tutorial-es blog-en blog-it blog-es; do
  if jq -e '.categories.performance.score' "./${id}.json" > /dev/null 2>&1; then

    a11y=$(jq -r '.categories.accessibility.score * 100 | round' "./${id}.json")
```
