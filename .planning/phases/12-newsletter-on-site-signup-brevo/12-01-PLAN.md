<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client -> /api/newsletter | Untrusted email, source, and honeypot fields cross from browser to server |
| /api/newsletter -> Brevo API | Server-side call with API key to external service |
| /api/newsletter -> Strapi API | Server-side call with API token to internal CMS |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-01 | Tampering | /api/newsletter body.source | mitigate | Validate source against VALID_SOURCES allowlist before use; default to 'inline' if invalid |
| T-12-02 | Tampering | /api/newsletter body.email | mitigate | Server-side regex validation via existing isValidEmail(); Brevo also validates |
| T-12-03 | Denial of Service | /api/newsletter | mitigate | SQLite rate-limit 5/IP/hour (checkRateLimit with windowMs=3_600_000) |
| T-12-04 | Spoofing | Bot form submissions | mitigate | Honeypot field (body.website) returns 403 before any processing |
| T-12-05 | Information Disclosure | BREVO_API_KEY in client | accept | Key is server-side only (import.meta.env in SSR route, never sent to client) |
| T-12-06 | Tampering | XSS via email field | mitigate | Email is never rendered back in HTML unescaped; only used in API calls |
</threat_model>
