<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Astro SSR render -> HTML response | Attacker-controlled fields in StrapiMedia.url could inject path characters into the /cdn-cgi/image/ URL if not properly encoded. |
| Browser -> Cloudflare edge (/cdn-cgi/image/) | Edge enforces Sources allowlist (configured in Plan 01); this plan must not emit origins that bypass the allowlist (not exploitable but could 4xx and hide images). |
| Astro SSR -> OpenGraph scrapers (Facebook/X/LinkedIn/Slack/Discord) | Scrapers may not follow /cdn-cgi/image/ URLs reliably; og:image must stay raw. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10.1-05 | T (Tampering) | Image URL path-parameter injection via StrapiMedia.url | mitigate | In `getStrapiMediaURL`, apply `encodeURI(sourceUrl)` before concatenation into the /cdn-cgi/image/ path (protects against a hostile CMS field containing `/../` or newline). Cloudflare's URL-parsing normalizes /cdn-cgi/image/{params}/{url} — injection cannot escape into params, but encodeURI keeps the path well-formed. Covered by a dedicated unit test: `it('URL-encodes origin with spaces / unsafe chars', ...)`. |
| T-10.1-06 | I (Information Disclosure) | og:image leaking transformed URL to scrapers that 404 it | mitigate | Blog [slug] pages pass `{raw:true}` for ogImage so the og:image <meta> emits the raw Strapi URL. Social scrapers are tested only indirectly (acceptance: grep the rendered HTML for the pattern `meta property="og:image" content="https://cms.bbq-experience.com/"`). |
| T-10.1-07 | D (DoS via cache stampede) | 5000/month free-tier cap on unique transforms | accept | ~300-800 unique transforms projected per RESEARCH; safely below cap. Manual monitoring via Cloudflare dashboard. Not blocking. |
| T-10.1-08 | T (Tampering) | Review [slug] ogImage uses /api/og-image server-generated card — not subject to this phase's URL rewrite. Unchanged path. | accept | Existing threat model from Phase 9 continues to apply unchanged. |
| T-10.1-09 | I (Information Disclosure) | Preload URL mismatch with <img src> triggering double-fetch (not a security issue per se, but a performance regression — tracked as a defect) | mitigate | Acceptance test: grep `dist/` build output for any page where `<link rel=preload as=image href="X">` and the page's largest `<img srcset>` entry don't share the same width query. Covered by Task 2 automated check. |
</threat_model>
